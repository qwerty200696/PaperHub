# 筛选区 UX 统一重构经验总结

## 📅 时间：2026.5.3

## 一、问题背景

### 1.1 重构前的混乱状态

重构前，三个模块的筛选区各自为政，用户体验极差：

| 层级 | 论文库 | 文章库 | 笔记库 | 混乱程度 |
|------|-------|-------|--------|---------|
| **第一层** | 阅读状态 | 文章来源 → 阅读状态 | 笔记分类 → 笔记状态 | ❌ 顺序完全乱 |
| **第二层** | 按来源筛选 | 文章来源 | 笔记分类 | ❌ 文案三个样 |
| **第三层** | 用户标签 | 文章标签 | 笔记标签 | ❌ 不一致 |

**具体表现：**
- 🔴 顺序完全不同：论文库「阅读状态」在最上面，笔记库「笔记分类」在最上面
- 🔴 文案不统一：「阅读状态」vs「笔记状态」，「按来源筛选」vs「文章来源」vs「笔记分类」
- 🔴 选项过时：论文库来源筛选还有历史遗留的「微信URL、对话笔记、知乎专栏」，但数据早就迁移了
- 🔴 交互逻辑不统一：有的是toggle，有的是直接赋值
- 🔴 筛选不生效：UI改了但逻辑模块没同步更新

---

## 二、重构过程

### 2.1 第一步：统一筛选顺序 ✅

**原则：把最常用的筛选放最上面**

最终统一顺序（从上到下）：
1. **📚 阅读状态** - 用户最常用的筛选，三个模块都有
2. **📂 内容分类** - 二级分类，各模块显示不同的具体选项
3. **🏷️ 标签筛选** - 三级筛选，各模块独立的标签系统

**为什么这个顺序？**
- 80% 的用户进来第一件事就是看「待读」或「在读」
- 其次才会按来源/分类筛选
- 标签是最精细的筛选，用得最少

### 2.2 第二步：统一文案 ✅

**原则：相同功能用相同文案，不同功能明确区分**

| 层级 | 统一前（三种写法） | 统一后 |
|------|------------------|--------|
| 第一层 | 阅读状态 / 阅读状态 / 笔记状态 | **📚 阅读状态** |
| 第二层 | 按来源筛选 / 文章来源 / 笔记分类 | **📂 内容分类** |
| 第三层 | 用户标签 / 文章标签 / 笔记标签 | **各自明确命名** |

**关键决策：第三层不统一！**
- 三个模块的标签是三个完全独立的数据库表
- 点击「论文标签」筛选的是论文，不会影响文章、笔记
- 明确叫「论文标签」、「文章标签」、「笔记标签」，用户一目了然知道这是三套独立的体系

> 💡 **UX 平衡艺术：在统一中保持清晰，在清晰中保持一致！**

### 2.3 第三步：统一交互逻辑 ✅

**所有模块完全相同的交互：**

```javascript
// 点击「全部」→ 清除筛选
@click="toggleXXXFilter(null)"

// 点击具体选项 → 选中该分类
@click="toggleXXXFilter(value)"

// 视觉状态完全一致
:type="选中 ? 'primary' : ''"
:effect="选中 ? 'dark' : 'plain'"
```

### 2.4 第四步：修复过时数据 ✅

**论文库来源筛选重构前后：**

| 重构前（错误） | 重构后（正确） |
|---------------|---------------|
| arXiv | 📄 arXiv |
| 微信URL（已迁移到文章库，0篇） | 📁 本地PDF |
| 对话笔记（已迁移到笔记库，0篇） | - |
| 知乎专栏（已迁移到文章库，0篇） | - |

**数据验证：**
```sql
SELECT source, COUNT(*) FROM papers GROUP BY source
-- 结果: arxiv: 3, pdf: 1
```

### 2.5 第五步：同步逻辑模块 ✅

**踩过的大坑！**

> ❌ **Bug 现场回放：**
> - 改了 index.html 里的点击事件为 `selectedSource = value`
> - 但筛选逻辑是在 `filterModule.js` 里，需要调用 `toggleSourceFilter(source, loadPapers)`
> - 结果：UI 变了但筛选根本不生效！

**教训：**
- ✅ 修改 UI 后一定要检查逻辑层
- ✅ 特别是分离了模块的代码，有两处配置
- ✅ 修改完一定要点一下测试筛选是否真的生效

## 三、UX 设计原则总结

### 3.1 一致性原则的四层境界

| 境界 | 做到了什么 | 用户感受 |
|------|-----------|---------|
| 第一层 | 位置相同 | "嗯，都在左边" |
| 第二层 | 顺序相同 | "哦，先看状态，再看分类" |
| 第三层 | 文案相同 | "哇，名字都一样！" |
| 第四层 | 交互相同 | **「我在一个模块学会了，另一个模块不用学！」** |

### 3.2 什么时候不应该追求 100% 统一？

**反例：第三层标签我们故意不统一**
- ❌ 如果强行都叫「内容标签」，用户会困惑："我点这个标签，到底筛选的是什么？"
- ✅ 明确叫「论文标签」、「文章标签」、「笔记标签」，用户一眼就懂

> 💡 **黄金法则：相同的东西要统一，不同的东西要明确！**

## 四、技术踩坑记录

### 🐛 坑 #1：修改了 UI 忘了同步逻辑模块

**现象：** 点击筛选按钮视觉变了，但列表没变化

**原因：**
```javascript
// ❌ 我改成了直接赋值，但这样不会触发 reload
@click="selectedSource = source.value"

// ✅ 正确做法：调用封装好的函数，内部会自动 reload
@click="toggleSourceFilter(source.value)"
```

**修复方案：**
1. 模板里的点击事件恢复调用 `toggleSourceFilter`
2. `filterModule.js` 里的配置也要同步更新
3. 一定要点一下测试是否真的生效

## 五、最终成果

### 5.1 三大模块 100% 统一的筛选区

```
📚 阅读状态
  ⏳ 待读  📖 在读  ✅ 已读  🔥 精读

📂 内容分类
  （论文库：📄 arXiv / 📁 本地PDF）
  （文章库：📱 微信 / 💡 知乎）
  （笔记库：📚 论文笔记 / ✏️ 自由笔记）

🏷️ xxx标签
  （各模块独立的标签系统）
```

### 5.2 用户收益

1. **零学习成本** - 在一个模块学会的操作，另外两个模块直接就会用
2. **零认知负担** - 相同的位置、相同的顺序、相同的名字、相同的交互
3. **零困惑** - 明确区分什么是共用的，什么是各模块自己的

> 🚀 **真正的 UX 优化：用户用起来觉得"理所当然"，根本感觉不到你做了优化。**

---

## 六、给未来重构的建议

1. ✅ **重构先改文案和顺序，再改逻辑**
2. ✅ **改完一处，一定要搜索是否还有其他地方需要同步**
3. ✅ **一定要实际点击测试，不要只看代码改了**
4. ✅ **统一不是为了统一而统一，要考虑用户的实际认知**
5. ✅ **文档要跟上，把踩过的坑记下来**
