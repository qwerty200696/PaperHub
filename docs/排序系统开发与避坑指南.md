# 排序系统开发与避坑指南

---

## 一、功能概述

PaperHub 论文库、文章库、笔记库实现了统一的排序系统，支持 5 种灵活的排序方式，全部在前端纯内存计算，毫秒级响应。

**三库排序偏好独立持久化**，刷新页面后自动恢复上次选择的排序方式。

| 排序选项 | 说明 | 算法 |
|---------|------|------|
| 🕒 按添加时间 | **默认值**，新入库的排在前面 | `created_at` 倒序 |
| ⭐ 收藏优先 | 标星文章置顶，同优先级按阅读状态再按时间 | 标星权重 → 阅读状态权重 → 时间 |
| 📚 阅读状态 | 按进度优先级排列 | 待读 → 在读 → 精读 → 已读 |
| 📅 发布日期 | 按文章发布时间 | `published_at` 倒序 |
| 🔤 标题排序 | 中文拼音 A-Z | `localeCompare('zh-CN')` |

## 二、核心代码架构

### 2.1 论文库排序

```javascript
// 初始化时从 localStorage 加载排序偏好
const sortBy = ref(localStorage.getItem('paper_sort_by') || 'created_at');

// 纯函数排序器 - 不修改原数组
const sortPapers = (list) => {
    const papers = [...list];  // 副本，不影响缓存
    switch (sortBy.value) {
        case 'status':
            papers.sort(/* 状态排序逻辑 */);
            break;
        // ... 其他排序
    }
    return papers;
};

// 排序偏好变化时保存到 localStorage
watch(sortBy, (newVal) => {
    localStorage.setItem('paper_sort_by', newVal);
});
```

### 2.2 三库独立持久化

```javascript
// 论文库排序
const sortBy = ref(localStorage.getItem('paper_sort_by') || 'created_at');

// 文章库排序
const articleSortBy = ref(localStorage.getItem('article_sort_by') || 'created_at');

// 笔记库排序
const noteSortBy = ref(localStorage.getItem('note_sort_by') || 'created_at');
```

**设计优点：**
- 原始数据只存一份在 `allPapersCache`
- 切换排序不需要重新请求 API
- 纯函数保证可预测，便于测试
- 三库排序偏好独立持久化，互不干扰

## 三、💥 史诗级大坑：`||` vs `??` 运算符

### 3.1 问题现象

**目标排序：**
```
待读 → 在读 → 精读 → 已读
```
（精读 = 已读 + 重要，排在普通已读前面）

**有 bug 时的排序：**
```
在读 → 精读 → 已读 → 待读  （待读诡异的排在最后！）
```

### 3.2 根因排查

```javascript
// 权重定义
const statusOrder = { 
    pending: 0,    // 待读 = 权重 0（排最前）
    reading: 1,    // 在读 = 权重 1
    mastered: 2,   // 精读 = 权重 2（精读比已读重要！）
    done: 3        // 已读 = 权重 3（排最后）
};

// ❌ 错误写法
papers.sort((a, b) => {
    const aStatus = statusOrder[a.status] || 9;  // 坑在这里！
    return aStatus - bStatus;
});
```

### 3.3 终极真相：JavaScript 的 falsy 规则

| 表达式 | 实际结果 | 说明 |
|--------|---------|------|
| `0 || 9` | **9** ❌ | `0` 在 JS 里被判定为 falsy！ |
| `1 || 9` | 1 | 正常 |
| `undefined || 9` | 9 | 正常 |

**所以 `pending: 0` 最终变成了 9！权重最高，当然排在最后。**

### 3.4 ✅ 正确解法

```javascript
// ✅ 使用空值合并运算符 ??
papers.sort((a, b) => {
    const aStatus = statusOrder[a.status] ?? 9;
    return aStatus - bStatus;
});
```

`??` 只对 `null / undefined` 生效，对 `0, '', false, NaN` 完全不影响！

| 表达式 | 实际结果 | 说明 |
|--------|---------|------|
| `0 ?? 9` | **0** ✅ | 正确！ |
| `1 ?? 9` | 1 | 正常 |
| `undefined ?? 9` | 9 | 正常 |

## 四、避坑金律

### 🚩 规则 1：只要权重可能为 0，永远用 `??`

```javascript
// ✅ 推荐
const weight = map[key] ?? 999;

// ❌ 禁止
const weight = map[key] || 999;
```

### 🚩 规则 2：写排序必须加单元测试

```javascript
// 每次写完，必须跑一遍验证
const test = [
    { title: 'A待读', status: 'pending' },
    { title: 'B已读', status: 'done' },
    { title: 'C精读', status: 'mastered' },
    { title: 'D在读', status: 'reading' },
];

test.sort(你的排序函数);
console.log(test.map(x => x.title));
// 期望输出：['A待读', 'D在读', 'C精读', 'B已读']
```

### 🚩 规则 3：前端排序要注意中文

```javascript
// ❌ 英文排序，中文乱码
a.title.localeCompare(b.title);

// ✅ 中文正确排序
a.title.localeCompare(b.title, 'zh-CN');
```

## 六、调试工具

开发时可以在控制台快速验证排序：

```javascript
// 浏览器 F12 输入：
const statusOrder = { pending: 0, reading: 1, done: 2, mastered: 3 };
const papers = ['pending', 'reading', 'done', 'mastered'].map(s => ({status:s}));

// 验证你的排序函数
papers.sort((a,b) => (statusOrder[a.status] ?? 9) - (statusOrder[b.status] ?? 9));
console.log(papers.map(x => x.status));
```
