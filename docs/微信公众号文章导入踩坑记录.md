## 🔴 踩坑全记录

### 🚫 坑1: 微信CDN防盗链问题
**现象**:
- 导入文章后，图片显示"图片来自微信公众平台，未经允许不可引用"
- 浏览器控制台显示 403 Forbidden

**根因**:
- 微信CDN `mmbiz.qpic.cn` 开启了防盗链保护，检查 HTTP Referer
- 非微信域名下无法直接引用微信CDN图片

**解决方案**:
- **不使用任何微信CDN地址**，全部强制替换为本地文件路径
- 导入时删除所有图片的 `src`, `data-src`, `data-original-src` 属性
- 按img标签出现顺序直接映射到本地assets文件夹的文件

```python
# 关键代码
for i, img in enumerate(soup.find_all('img')):
    for attr in ['src', 'data-src', 'data-original-src']:
        if img.has_attr(attr):
            del img[attr]  # 强制清除所有微信原始地址
    
    if i < len(local_files):
        img['src'] = f'./{article_id}_files/{local_files[i].name}'
    else:
        img.decompose()
```

**教训**: 不要相信HTML中的任何原始图片地址，本地文件才是王道！

### 🚫 坑2: iframe相对路径解析错误
**现象**:
- 本地直接打开HTML文件，图片显示正常
- 前端iframe打开 `/api/papers/3/download`，图片全部404

**根因**:
```
本地文件系统:
  HTML文件:  29476257.html
  图片文件夹: 29476257_files/
  相对路径: ./29476257_files/0  → 正确！

浏览器iframe:
  当前URL:   /api/papers/3/download
  图片路径:  ./29476257_files/0
  实际访问:  /api/papers/3/29476257_files/0  → 404！
```

**解决方案**:
- 在HTML的 `<head>` 中动态注入 `<base>` 标签修正基准路径

```python
base_dir = f'/api/papers/{paper_id}/images/'
html_content = html_content.replace('<head>', f'<head><base href="{base_dir}">')
```

最终效果:
```
BASE HREF: /api/papers/3/images/
IMG SRC:   ./29476257_files/0
实际访问:  /api/papers/3/images/29476257_files/0  → 200 OK！
```

**教训**: iframe中的相对路径不是相对于HTML文件位置，而是相对于当前浏览器URL！

### 🚫 坑3: 图片编号不匹配问题
**现象**:
- HTML中img的 `data-index="0"`, `data-imgfileid="503474619"`
- 本地文件实际叫 `0`, `0(1)`, `300`, `640`, `640(1)`...
- 按data-imgfileid找文件根本找不到

**根因**:
- 浏览器保存网页时，对图片文件进行了重命名
- HTML原始属性和本地文件名完全无对应关系

**解决方案**:
- **放弃所有属性匹配**，纯粹按出现顺序一一对应
- 第0张img → 文件夹第0个文件
- 第1张img → 文件夹第1个文件
- ...以此类推

```python
local_files = sorted([f for f in Path(assets_folder).iterdir() if f.is_file()])

for i, img in enumerate(soup.find_all('img')):
    if i < len(local_files):
        img['src'] = f'./{article_id}_files/{local_files[i].name}'
    else:
        img.decompose()  # 文件不够就删掉多余img
```

**教训**: 浏览器"另存为"产生的文件名和HTML原始数据没有任何关联，顺序才是唯一可靠的映射！

### 🚫 坑4: 数据库去重导致文件不匹配
**现象**:
- 重复导入同一篇文章时，去重机制返回已存在的paper_id
- 但HTML文件和图片文件夹已被重新生成，article_id变了
- 数据库存的旧file_path指向不存在的文件

**根因**:
- 去重检查通过标题匹配，返回旧paper_id
- 但解析函数还是生成了新的文件和新的article_id
- 数据库路径和磁盘文件不对应

**临时解决方案**（下载API层兜底）:
```python
# 微信文章强制使用最新生成的HTML文件，忽略数据库路径
if paper and paper.source == 'wechat':
    html_files = sorted(wechat_dir.glob('*.html'), key=lambda p: p.stat().st_mtime, reverse=True)
    if html_files:
        latest_html = html_files[0]  # 直接取修改时间最新的
        # ...渲染HTML
```

**根本解决方案**: 去重成功时应该跳过文件生成逻辑

**教训**: 去重逻辑和文件生成逻辑必须保持原子性！

### 🚫 坑8: 本地导入不传图片文件夹，assets_folder永远是None！
**现象**:
- 本地HTML导入后，图片永远是微信CDN
- 图片替换分支 `if src_folder_name:` 永远不执行

**根因**:
```python
def parse_local_html(html_path, assets_folder=None):
    # assets_folder = None ！！！
    # 代码里从来没有自动查找过文件夹！
    
    if src_folder_name:  # False，整个分支跳过！
        # 所有图片替换逻辑永不执行！
```

- Flask上传只传单个HTML文件
- 浏览器不会自动上传整个 `xxx_files` 文件夹
- 虽然HTML和图片在你电脑同一个目录，但服务器根本不知道！

**终极解决方案**:
- **放弃本地文件夹依赖**！
- HTML里的 `data-src` 本来就有完整的图片URL！
- 直接下载重新保存就行！跟URL导入逻辑完全一样！

```python
# 不再需要图片文件夹了！
for img in content_elem.find_all('img'):
    img_url = img.get('data-src', '') or img.get('src', '')
    # 直接从URL下载，跟浏览器另存为的文件夹彻底拜拜！
```

**教训**: 上传单个HTML就够了！不要信任任何本地资源路径！

### 🚫 坑9: Flask send_from_directory 安全拦截子目录！
**现象**:
- 图片URL: `/api/papers/7/images/65348469_files/0.png`
- 永远404！但文件确实存在！

**根因**:
```python
@app.route('/images/<path:filename>')
def serve(filename):
    # filename = "65348469_files/0.png"
    return send_from_directory(dir, filename)  # ❌ 安全检查不通过！
```

Flask的 `send_from_directory` 有路径遍历攻击防护，`filename` 里有 `/` 就直接拦截！

**解决方案**: 路由拆成两段
```python
# 改前
/images/<path:filename>

# 改后
/images/<folder>/<filename>
```

**教训**: Flask安全机制不是摆设，子目录老老实实拆成参数！

### 🚫 坑10: 样式隐身术，正文永远透明看不见！
**现象**:
- HTML文件大小80KB，内容都在！
- 浏览器打开只有标题！正文一片空白！

**根因**:
```html
<div id="js_content" style="visibility: hidden; opacity: 0;">
    全部正文30000多字都在这里！
    但CSS设置了：完全透明 + 完全不可见！！
</div>
```

微信靠前端JS延迟1秒后显示内容，但保存HTML后没有JS执行！
→ 正文永久隐身！

**解决方案**:
```python
def clean_content(content_elem):
    # 破除微信隐身术！
    del content_elem['style']
    content_elem['style'] = 'visibility: visible; opacity: 1;'
```

**教训**: 微信为了反爬，给你看的是HTML，但给你看的不是HTML！

### 🚫 坑11: JS隐身术，时间位置永远拿不到！
**现象**:
- 正文、标题都能提取到
- 但 `#publish_time` 元素永远是空的！
- IP地理位置也永远是空的！
- 浏览器打开就能看到，用requests拿HTML就看不到！

**根因**:
```html
<!-- HTML源代码里是空标签！ -->
<em id="publish_time"></em>

<!-- JS代码里才藏着真正的时间戳！ -->
<script>
var t = 1777261602;  // 2026-04-27 11:46:42
// 页面onload后用JS格式化时间并填入空标签
document.getElementById('publish_time').innerHTML = formatTime(t);
</script>
```

| 内容 | 存放方式 | requests能拿到吗？ | 浏览器打开能看到吗？ |
|------|---------|-------------------|---------------------|
| 文章正文 | 静态写死HTML | ✅ 直接拿到 | ✅ |
| 发布时间 | JS动态渲染 | ❌ 初始是空 | ✅ 等JS执行完 |
| IP地理位置 | JS动态渲染 | ❌ 初始是空 | ✅ 等JS执行完 |

**解决方案**:
```python
# 之前（错误）：自己拼HTML模板，丢失所有JS代码
with open(save_path, 'w') as f:
    f.write('<h1>' + title + '</h1>')
    f.write('<div class="date">' + fake_time + '</div>')
    f.write(str(content_elem))

# 现在（正确）：完整保存整个HTML，包括所有JS！
for style in soup.find_all('style'):
    style.decompose()  # 只删掉干扰样式
with open(save_path, 'w') as f:
    f.write(str(soup))  # JS全部保留！
```

👉 iframe打开时浏览器自动执行JS → 时间、位置自动出现！

**教训**: 别自作聪明重新拼HTML！完整保留才是最省心的终极方案！

**解决方案**: 使用新的第三方API `https://down.mptext.top/api/public/v1/download`

**新增函数**:
```python
def fetch_wechat_article_new(url, format='html'):
    """使用新API获取微信文章内容"""
    import requests
    from urllib.parse import quote
    
    params = {
        'url': quote(url),
        'format': format  # 支持 html/markdown/text/json
    }
    response = requests.get('https://down.mptext.top/api/public/v1/download', params=params)
    return response.text
```

**特点**:
- ✅ 无需API密钥
- ✅ 默认返回HTML格式
- ✅ 支持多种输出格式
- ✅ 保留旧函数 `fetch_wechat_article()` 向后兼容

### ✅ 优化13: 图片本地化处理
**问题**: 新API返回的HTML中图片使用网络URL，加载速度慢且依赖网络

**解决方案**:
```python
# 遍历所有img标签，下载图片并替换为本地路径
for i, img in enumerate(soup.find_all('img')):
    img_url = img.get('data-src', '') or img.get('src', '')
    if img_url.startswith('http'):
        img_resp = requests.get(img_url, headers=headers, timeout=10)
        if img_resp.status_code == 200:
            local_file = f'{i}{ext}'
            with open(images_dir / local_file, 'wb') as f:
                f.write(img_resp.content)
            img['src'] = f'./{article_id}_files/{local_file}'
    else:
        img.decompose()
```

**效果**: 图片保存到本地，加载更快，支持离线查看
