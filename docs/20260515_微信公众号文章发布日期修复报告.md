# 微信公众号文章发布日期修复报告

## 问题描述

用户反馈：从公众号订阅功能检索并导入的文章"期待！上海新一波演唱会定档开票！"，实际是今天（2026-05-15）发布的，但数据库中显示的发布日期却是 2026-03-20。

## 根本原因

在 `backend/services/wechat_parser.py` 中的 `_extract_published_at_only()` 函数和 `fetch_wechat_article()` 函数中，存在一个时间戳估算逻辑错误：

```python
# 原代码（错误）
if timestamps:
    estimated_ts = sorted(timestamps)[len(timestamps) // 3]  # ❌ 取三分之一位置的值
    published_at = datetime.fromtimestamp(estimated_ts)
```

这个算法取了所有时间戳排序后位于**三分之一位置**的值，而不是最新的时间戳。对于一篇今天发布的文章，页面中可能包含多个时间戳（如页面加载时间、评论时间、分享时间等），取中间值会导致获取到一个较早的时间戳，从而得到错误的日期。

## 解决方案

将时间戳估算逻辑改为使用**最大的有效时间戳**（即最近的时间）：

```python
# 修复后代码（正确）
if timestamps:
    # 使用最大的有效时间戳（最近的时间）作为发布时间
    estimated_ts = max(timestamps)  # ✅ 取最大值
    published_at = datetime.fromtimestamp(estimated_ts)
```

## 技术细节

### 时间戳提取逻辑

当从页面元数据无法直接提取到发布日期，或者提取到的日期是今天时，系统会：

1. 扫描HTML中的所有10位数字时间戳
2. 过滤出合理范围内的时间戳（大于2023-11-15且小于当前时间前1小时）
3. **修复前**：取排序后三分之一位置的值（可能导致日期偏早）
4. **修复后**：取最大值（确保使用最近的发布时间）

### 为什么取最大值更合理？

- 微信公众号文章页面中包含多个时间戳：
  - 文章发布时间（我们需要的）
  - 页面生成时间
  - 评论时间
  - 分享时间
  - 其他动态内容的时间戳
  
- 文章发布时间通常是这些时间戳中**最新的**（或接近最新的）
- 取最大值可以确保获取到最接近真实发布时间的值
