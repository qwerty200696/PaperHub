# 公众号订阅全选按钮响应性修复报告

## 问题描述

在「入库 → 公众号订阅（单选）」页面中，「✨ 批量备份到精选公众号」旁边的全选/取消全选按钮存在以下 Bug：

### Bug 1：文案不随选中状态同步

- 全选后按钮显示「取消全选 (5/5)」，此时手动取消勾选某篇文章，按钮文案仍停留在「取消全选 (5/5)」，不会变为「全选 (4/5)」
- 点击「取消全选 (5/5)」按钮后，所有文章确实被取消勾选，但文案仍显示「取消全选 (5/5)」，不会变为「全选 (0/5)」

### Bug 2：已导入文章无法选中

- 已导入文章的 checkbox 被 `:disabled="article.imported"` 禁用，无法参与批量备份操作

### Bug 3：后端备份接口变量名错误

- `wechat_subscriptions.py` 第 193 行引用了不存在的变量 `updated_lines`，应为 `all_articles`，导致备份成功时抛出 `NameError`

---

## 根因分析

### 核心问题：el-checkbox 受控模式下 @change 事件不可靠

原始代码同时使用了两种机制来修改 `selectedArticles`：

```html
<!-- 原始写法 -->
<el-checkbox
    v-model="selectedArticles"
    :value="article.url"
    @click.stop
></el-checkbox>
```

```javascript
// 卡片点击也触发
@click="toggleArticleSelection(article.url)"
```

**问题链条：**

1. `v-model="selectedArticles"` + `:value="article.url"` 是 Element Plus 的数组绑定模式，checkbox 内部会直接操作数组
2. `@click.stop` 阻止了事件冒泡，所以卡片上的 `toggleArticleSelection` 不会被触发
3. 但 Element Plus 内部对数组的操作方式（可能使用 splice/push 或替换整个数组）与 Vue 3 的响应性追踪存在兼容性问题
4. 当 `selectedArticles` 被 Element Plus 内部修改后，`allArticlesSelected` computed 属性没有重新计算

**第一次修复尝试（不完全）：**

将 `v-model` 改为 `:model-value` + `@change` 的受控模式：

```html
<el-checkbox
    :model-value="selectedArticles.includes(article.url)"
    @change="toggleArticleSelection(article.url)"
    @click.stop
></el-checkbox>
```

这个改法在「从无到有」选中时正常工作，但**从全选状态取消勾选时 `@change` 事件不触发**。原因是 Element Plus 在受控模式下，当内部状态与 `:model-value` prop 不一致时，可能会吞掉事件。

### 次要问题：数组原地修改 vs 替换

`toggleArticleSelection` 中使用 `splice` 和 `push` 原地修改数组：

```javascript
selectedArticles.value.splice(index, 1);  // 原地删除
selectedArticles.value.push(url);          // 原地添加
```

Vue 3 的 `ref` 对数组的 `splice`/`push` 有响应性支持，但当与 Element Plus 的内部操作同时作用于同一数组时，可能导致响应性追踪断裂。

---

## 最终修复方案

### 修复 1：将点击处理上移到外层容器

让 `el-checkbox` 变成纯视觉组件，不再依赖 Element Plus 的事件系统：

```html
<!-- 修复后 -->
<div class="article-checkbox-area" @click.stop="toggleArticleSelection(article.url)">
    <el-checkbox
        :model-value="selectedArticles.includes(article.url)"
        class="custom-checkbox"
    ></el-checkbox>
    ...
</div>
```

**关键点：**
- `el-checkbox` 只绑定 `:model-value`，不绑定 `@change`，不绑定 `@click.stop`
- 点击事件由外层 `article-checkbox-area` 的 `@click.stop` 统一处理
- `@click.stop` 阻止冒泡到卡片，避免与卡片的 `@click` 双触发
- checkbox 变成纯展示组件，视觉状态完全由 `:model-value` 控制

### 修复 2：数组替换代替原地修改

```javascript
// 修复前
selectedArticles.value.splice(index, 1);
selectedArticles.value.push(url);

// 修复后
selectedArticles.value = selectedArticles.value.filter(u => u !== url);
selectedArticles.value = [...selectedArticles.value, url];
```

数组替换（创建新引用）是最可靠的方式，确保 Vue 一定能检测到变化并触发 computed 重新计算。

### 修复 3：全选逻辑包含已导入文章

```javascript
// 修复前：排除已导入文章
selectedArticles.value = wechatArticles.value.filter(a => !a.imported).map(a => a.url);

// 修复后：包含所有文章
selectedArticles.value = wechatArticles.value.map(a => a.url);
```

同时移除 checkbox 的 `:disabled="article.imported"`，允许选中已导入文章进行批量备份。

### 修复 4：按钮文案格式

```html
<!-- 修复前 -->
{{ allArticlesSelected ? '✓ 取消全选' : '○ 全选未导入' }}

<!-- 修复后 -->
{{ allArticlesSelected ? '取消全选 (' + selectedArticles.length + '/' + selectableArticleCount + ')' : '全选 (' + selectedArticles.length + '/' + selectableArticleCount + ')' }}
```

新增 `selectableArticleCount` computed 属性，显示可选文章总数。

### 修复 5：后端变量名

```python
# 修复前
'article_count': len(updated_lines),  # NameError

# 修复后
'article_count': len(all_articles),
```

## 经验总结

### 1. Element Plus el-checkbox 的受控模式陷阱

在 Element Plus 2.x 中，`el-checkbox` 使用 `:model-value` 受控模式时，`@change` 事件不一定可靠触发。特别是在「从选中变为未选中」的场景下，事件可能被吞掉。

**最佳实践：** 当需要精确控制 checkbox 状态时，将 `el-checkbox` 当作纯展示组件使用（只绑定 `:model-value`），点击处理交给外层容器的 `@click` 事件。

### 2. Vue 3 响应性：数组替换优于原地修改

虽然 Vue 3 的 Proxy 机制支持追踪 `splice`/`push` 等原地修改，但在与第三方组件库（如 Element Plus）共享同一个响应式数组时，原地修改可能导致响应性追踪断裂。

**最佳实践：** 使用数组替换（`arr = arr.filter(...)` / `arr = [...arr, item]`）代替原地修改（`arr.splice()` / `arr.push()`），确保 Vue 一定能检测到变化。

### 3. 事件冒泡的精确控制

在嵌套的点击事件中，需要精确控制事件冒泡：

- 卡片 `@click` → 切换选中
- checkbox 区域 `@click.stop` → 切换选中 + 阻止冒泡（避免双触发）
- 其他按钮 `@click.stop` → 各自功能 + 阻止冒泡

**最佳实践：** 在同一层级只保留一个点击处理入口，避免多个事件处理器操作同一状态。
