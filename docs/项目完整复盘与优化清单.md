### 4.2 最值得借鉴的设计

#### 「前端统计标签关联数」架构

> **用一套后端 API，前端做三次过滤**，相比分开写三个 API：

| 指标 | 这个方案 | 分开写 API |
|------|---------|----------|
| 后端代码 | 0 行新增 | +100 行 |
| 数据库查询 | 1 次 | 3 次关联查询 |
| 代码复用 | 一套筛选逻辑 | 三套重复逻辑 |
| 迭代速度 | 5 分钟完成 | 半天 + 跑迁移 |

💡 **经验：数据量小的时候，前端算永远比后端算快！**

## 六、📐 设计方法论沉淀

### 6.1 「一致性」设计三原则

> 论文库有的，文章库、笔记库也要有，用户学习一次就够了！

| 层面 | 统一标准 |
|------|---------|
| **视觉** | 左侧色条配色完全一致：待读绿/在读蓝/已读灰/精镀金 |
| **布局** | 侧边栏：状态筛选在上，标签筛选在下 |
| **数据** | 排序算法：标星 → 状态 → 时间 |
| **交互** | 标签点击效果：plain/dark 两种状态 |

### 6.2 什么时候前端算，什么时候后端算？

| 场景 | 谁来算 | 为什么 |
|------|-------|-------|
| 数据量 < 1000 | ✅ 前端 | 快！不用写 API！ |
| 数据量 > 10000 | ✅ 后端 | 前端卡 |
| 需要权限校验 | ✅ 后端 | 安全 |
| 和前端展示数据一致 | ✅ 前端 | 没有一致性问题！ |
| 报表 / 统计 | ✅ 后端 | 数据准确 |
