#### 2. 列表页分页功能 ❌ 暂不适用

**现状核实**：经代码审查，当前列表页（论文库/文章库/笔记库）**并未实现分页功能**。

| 模块 | 后端分页 | 前端实际行为 |
|------|---------|-------------|
| 论文库 | 支持 `page`/`per_page` 参数 | 固定请求 `per_page=500`，一次性加载全部数据 |
| 文章库 | 不支持，返回全部数据 | 获取全部数据，无分页 UI |
| 笔记库 | 支持 `page`/`per_page` 参数 | 固定请求 `per_page=500`，一次性加载全部数据 |

**结论**："筛选后页码重置"问题在现有架构下不成立。列表页采用"大页码一次性加载 + 纯前端内存筛选"模式，筛选后自动显示全部符合条件的数据，不存在空页体验。

**后续决策**：若数据量增长到需要分页时，再统一实现前端分页 + 筛选后重置页码逻辑。

```python

import chromadb

client = chromadb.Client()
collection = client.create_collection("papers")

# 论文入库时生成 embedding
def index_paper(paper):
    embedding = get_embedding(paper.title + paper.abstract)
    collection.add(ids=str(paper.id), embeddings=embedding)

# 自然语言搜索
def semantic_search(query):
    embedding = get_embedding(query)
    return collection.query(query_embeddings=embedding, n_results=10)
```

## 六、项目方法论总结

### 三大成功原则

1. **吃自己的狗粮** - 所有功能都是自己每天用出来的需求
2. **踩坑即文档** - 遇到的每一个坑都沉淀成经验
3. **一致性优先** - 宁愿功能少一个，也要交互统一

### 设计决策准则

| 场景 | 决策 |
|------|------|
| 数据量 < 1000 | 前端算更快 |
| 数据量 > 10000 | 后端算更稳 |
| 需要权限校验 | 后端做 |
| 和前端展示一致 | 前端算 |
| 报表/统计 | 后端做 |
