# PaperHub 大模型融入系统设计方案

---

## 💡 核心设计理念

> **不做大模型聊天机器人，做大模型增强的个人知识管理助手。**

大模型的价值不是和用户聊天，而是：
1. ✨ **自动化** - 自动处理用户不想做的脏活累活
2. 🎯 **个性化** - 基于用户本地知识库做推理
3. 🔗 **网络化** - 挖掘笔记/论文/文章之间隐藏的关联

---

## 一、大模型应用场景全景

### 1.1 入库阶段自动化

| 🌟 **质量评分** | 给论文/文章打分，识别高价值内容 | 海量内容中筛选精华 |

| 🗂️ **来源去重** | 不同来源讲同一件事的内容自动识别 | 消灭信息冗余 |

## 二、第一优先级：高价值低成本功能 ✨

### 🔥 1. 自动打标签（ROI 最高）

#### 工作流

```
用户点击入库 → 后台自动提取全文
                    ↓
            调用大模型分析内容
                    ↓
  ┌───────────────────────────────────┐
  │  从已有标签中推荐最匹配的 3-5 个     │
  │  +  推荐 1-2 个建议新增的标签        │
  └───────────────────────────────────┘
                    ↓
          用户确认 / 编辑 / 取消
                    ↓
          自动打标签入库完成
```

#### Prompt 模板

```python
SYSTEM_PROMPT = """
你是一个专业的学术文献分类助手。请基于内容和已有标签系统进行分类。

已有标签系统：
{existing_tags}

请分析以下文章内容：
标题：{title}
摘要：{abstract}
全文前2000字：{content_preview}

请输出：
1. 从已有标签中选择最匹配的 3-5 个，按匹配度排序
2. 推荐 1-2 个应该新增的标签
3. 简短理由（20字以内）

输出 JSON 格式：
{{
  "recommended_tags": ["tag1", "tag2"],
  "new_tags": ["new_tag1"],
  "reason": "理由"
}}
"""
```

#### 技术要点
- **Token 控制**：只传标题 + 摘要 + 前 2000 字，不要全文
- **冷启动策略**：先从已有标签中选，不要上来就新建
- **用户在回路**：一定要让用户确认，不要 100% 全自动

### 3.2 LLM Client 封装层

#### 核心设计原则
1. **可切换**：OpenAI 坏了切豆包，用户无感知
2. **可缓存**：同一篇论文的解读不要重复花钱
3. **可观测**：花了多少钱，用了多少 Token 一目了然

```python
# backend/services/llm_client.py
class LLMClient:
    def __init__(self, provider="openai", api_key=None):
        self.provider = provider
        self.api_key = api_key
        self.cache = {}  # 简单内存缓存
        self.token_usage = {
            "prompt_tokens": 0,
            "completion_tokens": 0,
            "total_cost": 0.0
        }
    
    def chat_completion(self, messages, temperature=0.0):
        # 1. Cache 命中直接返回
        cache_key = hash(str(messages))
        if cache_key in self.cache:
            return self.cache[cache_key]
        
        # 2. 根据 provider 调用不同 API
        if self.provider == "openai":
            result = self._call_openai(messages, temperature)
        elif self.provider == "doubao":
            result = self._call_doubao(messages, temperature)
        
        # 3. 记账 + 缓存
        self._update_usage(result)
        self.cache[cache_key] = result
        
        return result
```

### 3.3 Prompt Engine 层

所有 Prompt 集中管理：

```python
# backend/services/prompt_engine.py

PROMPTS = {
    "auto_tag": {
        "system": "你是专业的学术分类助手...",
        "template": "已有标签: {tags}\n内容: {content}\n请输出..."
    },
    "paper_summary": {
        "system": "你是资深算法工程师，擅长解读论文...",
        "template": "请分三个部分解读这篇论文：\n1. 核心创新点..."
    },
    "related_content": {
        "system": "你是知识管理专家，擅长发现内容关联...",
        "template": "当前内容：{current}\n候选内容：{candidates}\n请判断..."
    }
}

class PromptEngine:
    @staticmethod
    def build(tag, **kwargs):
        prompt = PROMPTS[tag]
        return [
            {"role": "system", "content": prompt["system"]},
            {"role": "user", "content": prompt["template"].format(**kwargs)}
        ]
```

## 五、关键设计决策

### ✅ 决策 1：不需要一开始就上向量数据库

**为什么？**
1. **成本高** - 切库 + 向量化 + 检索，至少多 3 天工作量
2. **体验提升有限** - 前两个功能完全不需要向量
3. **可以后加** - Phase 1/2 跑起来了，用户真有需要再加

**什么时候需要？**
- 本地内容 > 500 篇
- 用户想要自然语言问答，且希望能匹配全文

---

### ✅ 决策 2：用户永远在回路

**绝对不要做 100% 全自动**
- ❌ 自动打标签用户看不到 → 不信任
- ✅ 推荐标签给用户点确认 → 越用越准
- ❌ 后台静默跑 → 花钱如流水用户不知道
- ✅ 每一次调用都要有明确的用户触发 → 花钱花得明白

---

### ✅ 决策 3：Token 控制是第一要务

| 场景 | 发送内容量 | 预估 Token | 单次成本（GPT-3.5） |
|------|-----------|-----------|-------------------|
| 打标签 | 标题+摘要+前2000字 | ~800 | ¥0.012 |
| 论文解读 | 标题+摘要+前3000字 | ~1200 | ¥0.018 |
| 关联分析 | 5 篇候选 | ~1500 | ¥0.022 |

> 💡 按一天调用 50 次算，一天才一块钱！

**控制手段**：
1. ✅ 永远不要传全文，只传前 N 字
2. ✅ 强缓存，同一篇不重复调用
3. ✅ 可开关，用户随时可以关掉

#### Bug 修复: 笔记去重算法优化
- **问题**：不同论文的 AI 解读被误判为重复
- **原因**：字符级相似度对英文标题过于宽松
- **修复**：改用词级别 Jaccard 相似度（权重 60%）+ 字符级（20%）+ 编辑距离（20%）
- **效果**：两篇不同论文的相似度从 ≥0.8 降至 ~0.15
